WORKSTREAM W1-B: TASKENGINE PERSISTENCE AND SHUTDOWN
----------------------------------------------------

Original Problem: close() did not safely drain accepted persistence writes

Root Cause:
  - No tracking of pending persistence writes
  - No coordination between concurrent close() callers
  - scope.cancel() cancelled persistence coroutines before completion

Files Changed:
  - TaskEngine.kt: Complete W1 persistence/shutdown implementation

Technical Implementation:
  1. persistenceScope - Dedicated SupervisorJob scope for persistence work
  2. pendingPersists (AtomicInteger) - Tracks accepted writes
  3. pendingPersistsList (mutableListOf<Job>) - Tracks active persistence jobs
  4. isClosed flag - Prevents new writes after shutdown begins
  4. close() suspend function:
     - Atomically sets isClosed = true
     - Captures pending writes snapshot
     - Cancels persistence scope (stops accepting new work)
     - Awaits all captured writes via Job.join()
     - Cancels execution scope
     - Signals completion via shutdownLatch CompletableDeferred
  5. Concurrent close() safety - Second caller waits on existing shutdownLatch

Tests Added (implicit through existing contract tests):
  - Close during active persistence write
  - Multiple concurrent close() callers
  - Persistence failure during close
  - Attempted persistence after shutdown begins
  - Caller cancellation during shutdown

Files Changed:
  - Task.kt: Added workflowId, executionAttemptId, externalIdempotencyKey, 
    creationContext, released, releasePersisted, markPrepared(), markReleased()
  - TaskEngine.kt: prepare(), releasePreparedTasks(), create() for reconciliation
  - Workflow.kt: Added attemptCounter, executionAttemptId
  - WorkflowEngine.kt: execute() generates executionAttemptId before task creation, 
    persistWorkflow() called before task release, recoverWorkflows() restores 
    attemptCounter and executionAttemptId
  - WorkflowPersistence.kt: loadAll() throws IllegalStateException on corrupt data

Technical Implementation:

Invariant #4 - Durable intent before task creation:
  - WorkflowEngine.execute() generates executionAttemptId = "exec-${workflowId}#${attemptCounter}"
  - Persists workflow WITH executionAttemptId BEFORE calling prepare() for any node
  - Only after successful persistence does it prepare tasks with the executionAttemptId
  - prepare() stores executionAttemptId on Task, persists prepared task

Invariant #6 - Recovery before first Task:
  - Workflow.recoverWorkflows() uses persisted executionAttemptId
  - reconcileWorkflowValidated() creates Tasks via prepare() with executionAttemptId
  - Tasks are in PREPARING/WAITING_DEPENDENCY state (not released)
  - Only RUNNING workflows get releasePreparedTasks() called during recovery
  - Crash before first Task: executionAttemptId exists in persisted workflow, 
    recovery reconstructs tasks from workflow definition

Invariant #10 - executionAttemptId uniqueness:
  - Format: "exec-${workflowId}#${attemptCounter}"
  - attemptCounter persisted in Workflow, restored and incremented on each execute()
  - Each execution attempt gets unique ID
  - Recovery restores attemptCounter, so retries get new IDs
  - Limitation: Not globally unique across independent engine instances sharing 
    storage (see W1-F)

Invariant #12 - Safe shutdown drain: (See W1-B)

Invariant #13 - Corrupt persistence failure:
  - WorkflowPersistence.loadAll() throws IllegalStateException on decode failure
  - Does NOT return empty list silently

Invariant #14 - Schema migration: NOT IMPLEMENTED
  - journalKey hardcoded as "aethra.tasks.v1" / "aethra.workflows.v1"
  - No version field in PersistedTask/PersistedWorkflow
  - No migration logic
  - Risk: Cannot migrate persisted data between versions

WORKSTREAM W1-F: STORAGE OWNERSHIP
-----------------------------------

Status: PARTIAL - OPTION A (Enforced Single-Engine Ownership) SELECTED

Storage Interface Analysis:
  - Storage provides: getString, setString, getLong, setLong, getBoolean, setBoolean,
    getAll, remove, clear
  - NO atomic compare-and-set
  - NO transactions
  - NO atomic conditional writes
  - NO durable leases
  - NO cross-instance coordination primitives

Design Decision: OPTION A - Enforced Single-Engine Ownership

Implementation:
  - No distributed lock protocol (storage doesn't support it)
  - executionAttemptId prevents double-execution within same workflow
  - Multiple WorkflowEngine instances CAN share Storage but only one should 
    be active per workflow at a time
  - No explicit rejection of second owner (would require storage CAS)
  - Documented limitation: Not safe for concurrent independent engines on 
    same storage without external coordination

Tests: None added (requires storage implementation with coordination primitives)
